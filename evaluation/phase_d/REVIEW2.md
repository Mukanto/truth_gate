## Major findings

### R2-1 (major): §5 Clean pass (classification of failed clean passes); §8 I-D5

- **File:** phase_d/PREREG_PHASE_D_draft2.md; context: repo/truth_gate/checks.py
- **Passage:** "fixed not clean in these worlds (correct flag)": the flagged stream's rate is above the flag threshold, and its 95% Wilson interval excludes the declared size; "possible false alarm": the interval includes the declared size.
- **Reason:** The classification cannot find a false alarm, and it does not cover every failure. (1) The gate raises K2_HIGH_SIZE and HIGH_RATE:* exactly when wilson_lower(k, 200, alpha_family/(2m)) > size (check_k2, check_high_rate). Since alpha_family/(2m) <= 0.025 for every m >= 1, the gate's bound is at least as strict as a 95% (z = 1.96) Wilson bound. So every rate-flagged stream has, by construction, a rate above the threshold and a 95% interval that excludes the size. A valid fixed criterion (true rate 0.05) flagged by chance has probability about 0.012 at m = 4. Its count is then at least 18/200, whose 95% lower bound is 0.058, so it is labelled "correct flag". The rule judges the flag with the same count that raised it, which is circular. (2) K4_CONTROL_ALSO_HOLDS and K5_HOLDS_ON_NOISE/NULL/SHUFFLE are not rate-above-size tests: they fire when the stream is "not significantly lower than plus" (check_k4, check_k5). Take a fixed twin whose plus rate drops in W-1 worlds: plus 20/200 and noise 5/200 at m = 4 is not SL, so K5_HOLDS_ON_NOISE fires. Its noise rate (0.025) is below the threshold and its 95% interval is [0.011, 0.057]. It fails the first class, and the second applies only by accident; the real cause is low power in plus. (3) Failures through K2_NO_SEPARATION, K1_UNDEFINED, UNTESTED, a timeout or a load error fall in neither class. (4) I-D5 reads any W-1 deficit as "a limit of the checklist, not of the gate" and gives no opposite reading (PROTOCOL 1.4). One opposite reading: stronger dependence lowers the fixed criterion's power in plus, so the gate's relative rules fire.
- **Fix:** Replace the two classes with an ordered classification that uses an independent estimate, in a frozen tool (for example tools/clean_pass_class.py) with tests, run only after the run: (1) "fixed not clean in these worlds": for each flagged rate stream, draw 1000 fresh samples of that stream from the same declared world (seed 20261117, stream "classify:<stream>") and evaluate the fixed criterion; the class applies when the 95% Wilson interval of that fresh rate lies above the declared size; (2) "possible false alarm": the fresh interval includes the size; (3) "fixed weak in plus": the failure comes only from K2_NO_SEPARATION, K2_HOLDS_UNREACHABLE or a relative flag (K4_*, K5_*) whose stream rate is not above the threshold; (4) "attrition or no verdict", with the cause. In I-D5, add the opposite reading quoted above and report class (3) separately.

### R2-2 (major): §5 Attributable detection (missing counts); classify()

- **File:** phase_d/tools/tools/attributable.py; phase_d/PREREG_PHASE_D_draft2.md; phase_d/tools/tests/test_attributable.py
- **Passage:** "If the fixed study has no counts for s (a load error or a hard UNDEFINED), the detection is not attributable through s, and it is listed."
- **Reason:** The tool departs from this sentence on both of the cases it names. (1) The certificate of a study that fails to load has "components": [] (truth_gate/certificate.py, components=[] with load_error). classify() calls _component() on both bodies before anything else. So a load-error certificate of either twin raises ValueError ("expected one component, found 0"), and the CLI reports it as a usage error (exit 2). I ran both cases and both raise. Load errors are attrition in §6, scored as a miss or a failed clean pass. The primary-endpoint tool therefore crashes on an outcome the draft scores. (2) A hard UNDEFINED does not remove counts: the gate writes counts for every stream, with hard_undefined, and the tool tests them like any others. A fixed twin with K1_UNDEFINED and 50 hard failures on minus came out attributable in my check, where the draft says it is not. (3) test_fixed_without_counts mocks a body with one component and empty counts. No certificate has that shape, so neither case is tested.
- **Fix:** In classify(): (a) if the faulty body has no component or carries load_error, return pb_detected false, with the reason "faulty load error", and no exception; (b) if the fixed body has no component or carries load_error, or its counts on s have hard_undefined > 0, then s does not qualify and the reason is listed. Pick the hard-UNDEFINED reading in §5 ("hard_undefined > 0 on s" or "fixed verdict UNDEFINED through K1_UNDEFINED"). Correct the parenthesis to match the certificate: "no counts for s (a load error), or a hard UNDEFINED on s". Add tests with a real load-error body ({"verdict": "UNDEFINED", "components": [], "load_error": {...}}) for each twin, and one with a fixed hard-UNDEFINED body.

### R2-3 (major): §5 Fixture of attributable.py; §10

### R2-4 (major): §5 Structure in the declared worlds (miss labels); §8 I-D3

- **File:** phase_d/PREREG_PHASE_D_draft2.md; context: repo/truth_gate/checks.py
- **Passage:** "Each miss gets one label: (a) share below 0.5 ...; (b) structure present, and the faulty minus count at or below the flag threshold ...; (c) faulty study flagged, but the detection is not attributable ...; (d) faulty minus count above the flag threshold, but no flag: "gate"."
- **Reason:** (1) The conditions overlap and have no precedence. A miss can have share < 0.5 and be flagged without attribution ((a) and (c)). It can have a faulty minus count at or below the threshold and be flagged on a control or the noise probe ((b) and (c)). "One label" then becomes a choice made after the run. (2) As worded, (d) is almost unreachable. A faulty minus count above k* raises K2_HIGH_SIZE by construction (check_k2), and the verdict is NOT_FALSIFIABLE. The only exceptions are K1_UNDEFINED (verdict UNDEFINED) and an identical minus (suppressed, UNTESTED). So "gate" would in practice label criterion crashes on a W world, or an inert minus, which are not gate failures. (3) "The flag threshold" is not defined per arm. k* depends on the arm's m: 17 for m <= 2, 18 for m = 3 to 5, 19 for m = 6 to 14, 20 for m >= 15, and the W skeletons declare their own controls, null worlds and relational pairs. (4) Misses from attrition (invalid skeleton, part-B "no", timeout, load error) count under intention to treat but get no label. (5) No tool computes the labels, yet the I-D3 readings of every "fails" row rest on them.
- **Fix:** Define the labels as an ordered list, computed per pair and arm by a frozen tool with tests, and use the same list in I-D3: (e) attrition or no verdict (cause: invalid skeleton, part-B "no", timeout, load error, K1_UNDEFINED, UNTESTED); otherwise (c) PB-detected but not attributable; otherwise (a) structure share below 0.5 (not for "set by the brief"); otherwise (b) faulty minus count below k*_arm, with k*_arm computed from that arm's study through count_comparisons; otherwise (d) "other: examined as a possible gate finding". Another order is acceptable if it is fixed now.

### R2-6 (major): §0.3 Descriptive; §1 Decoys; §8 I-D2 decoy guard

- **File:** phase_d/PREREG_PHASE_D_draft2.md; phase_d/ALLOCATION_D.json (decoys); phase_d/WORLD_INSTRUCTIONS_D1.md
- **Passage:** "The decoy pairs (section 1) in both arms, to show the checklist's cost outside its target classes."
- **Reason:** Most decoy mechanisms are named by the checklist. B-6 units-not-independent (HUR84, LAZ10, LAZ18: three of the four B-6 decoys) is exactly "groups, sites, or repeated measurements of the same unit". ### R2-8 (major): §3 item 8 (skeleton check); dyn_check()

- **File:** phase_d/tools/tools/check_skeletons_d.py; phase_d/PREREG_PHASE_D_draft2.md
- **Passage:** "(draft) tools/check_skeletons_d.py checks every skeleton: keys, shapes, dtypes and the section 2.1 limits. / (code) if a.ndim != ndims[k]: ... "array dimensions not found in the brief text""
- **Reason:** The script checks only each key's number of axes, and that each dimension number appears somewhere in the brief's text (sizes, shapes, meanings or claim). It does not check the shape itself. A key transposed from the brief's (500, 200) to (200, 500) passes, and so does a size that matches a number in the claim. A transposed or resized key in one arm then becomes a hard UNDEFINED in that arm only (a miss and a failed clean pass under intention to treat), or a silent wrong analysis. Then make check_skeletons_d.py require a.shape == tuple(dims) for every key, world, control output and draw. In --case mode, also require identical shapes across reference.py, W0.py and W1.py. Add tests for a transposed key and for a key whose size equals a number in the claim.

## Overall judgment

Draft 2 is a substantial improvement and answers both blocking findings of review 1 in substance. The validity checks run on streams and a seed the gate never uses, and arm R is now a consistency check. The primary endpoint has one rule, a fixture computed from the Phase C certificates, and a documented secondary rule. Each role has a frozen instruction file.
