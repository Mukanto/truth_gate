# NOTES: interpretation choices (open points in the rule text)

Source of every quote: `inputs/RULE.md`. Reproduce with `py -I -B out/recompute.py` (standard library only; Fisher test written with `math.comb`, exact arithmetic via `fractions`).

## A. Inputs and structure

1. **Certificate layout.** I read `body.verdict`, `body.load_error`, `body.components[0].flags`, `.counts[s].{holds,n,hard_undefined}`, `.bounds[s].{lower,upper}`. The task statement names `components[0]`; every certificate has exactly one component (`C`) or none (load error). I ignore other components, `study_flags` (empty everywhere), `study_flag_details`, `errors` and `unresolvable` (empty everywhere). Rule text: "Read the certificate JSON structure from the files themselves" (task); the rule itself says nothing about study-level flags, only the flag table.
2. **Arms.** Rule: "both twins run in arm R (the reference worlds), arm W-0 and arm W-1." and "Attributable detection of a pair in an arm". Each pair folder holds one faulty/fixed certificate pair with no arm label. I compute one result per pair id and do not combine or choose among arms.
3. **Expected flags.** Rule: "Expected flags as PC §6, from `EXPECTED_FLAGS_D.json`." I use the `expected` list from `inputs/acceptance/Pxx/expected_flags.json` (acceptance) and `inputs/pc/EXPECTED_FLAGS.json` (PC), as the task says. `EXPECTED_FLAGS_D.json` itself was not given and not read.
4. **Count definition.** "counts" is `holds` out of `n` (not `n - undefined`). The rule says "the faulty count on s exceeds the fixed count" and never mentions undefined. Across all inputs `undefined > 0` occurs only on `probe:zeros` (never a rate-flag stream) and on P04 fixed `world:minus` (`hard_undefined` 50, handled by item 18), so this choice does not change any result.

## B. Which flags are rate flags

5. **Rate flag set = exactly the table rows.** Rule: the table of "Rate flags and their streams" and "`K2_NO_SEPARATION` alone is not a rate flag." Rate flags: `K2_HIGH_SIZE`, `K2_FAILS_UNREACHABLE`, `HIGH_RATE:control:<id>`, `K4_CONTROL_ALSO_HOLDS`, `K5_HOLDS_ON_NOISE`, `HIGH_RATE:probe:noise`, `K5_HOLDS_ON_NULL`, `HIGH_RATE:world:null`, `HIGH_RATE:probe:shuffle:<a>,<b>`, `K5_HOLDS_ON_SHUFFLE`. Everything else (`K2_NO_SEPARATION`, `K2_LOW_POWER`, `K1_UNDEFINED`, `K5_INCONCLUSIVE:*`, any other `HIGH_RATE:*` such as on `probe:zeros`, `world:plus`, `world:minus`) is not a rate flag. No `HIGH_RATE:` flag outside the four listed forms occurs in the data.
6. **HIGH_RATE stream name** is the text after `HIGH_RATE:` (so `HIGH_RATE:probe:shuffle:x,y` is stream `probe:shuffle:x,y`), taken to be the key in `counts`. Rule: "`HIGH_RATE:probe:shuffle:<a>,<b>` | that shuffle stream".
7. **"Control stream" and "shuffle stream"** (for the two bounds-based rules) are identified by key prefix `control:` and `probe:shuffle:`. Rule: "each control stream s with `bounds[s].upper ≥ bounds[world:plus].lower` (the gate's rule)".
8. **Bounds comparison** is inclusive (`≥`) on the stored (rounded to 12 digits) floats, no tolerance.
9. **Which twin's bounds.** The bounds-based flags (`K4_CONTROL_ALSO_HOLDS`, `K5_HOLDS_ON_SHUFFLE`) are mapped to streams with the bounds of the study that carries the flag: faulty flags use the faulty bounds, fixed flags use the fixed bounds. The rule says "`bounds[s]`" without naming a twin. Basis: the flag is a statement of the study that raises it ("the gate's rule"). Effect seen in the data: P03 faulty K4 maps to `control:permute_y` and fixed K4 maps to `control:permute_x`; P07 likewise for the shuffle streams. Other choices (union or intersection of the twins' bounds, fixed bounds for both) would change these pairs.
10. **`world:plus` missing** from bounds: a bounds-based flag then maps to no stream (listed as non-qualifying "flag maps to no stream"). Does not occur.

## C. Attributable detection

11. **Candidate flags must be present in the faulty study.** Rule: "The faulty study's verdict is NOT_FALSIFIABLE, and at least one of its expected rate flags, on a stream s, meets both conditions". I read "its expected rate flags" as the faulty study's flags that are also expected and are rate flags. A flag that is expected but not in `components[0].flags` of the faulty twin is not a candidate. Sensitivity (recorded per pair in `RESULTS.json` as `sensitivity_expected_flag_need_not_be_present`): if expected-but-absent rate flags were also candidates (mapped by the faulty bounds), the counts do not change (acceptance 4/1/3, PC 10/7/8).
12. **Verdict gate.** Attributable requires faulty verdict exactly `NOT_FALSIFIABLE`. Stream-level qualification is still computed for every pair; if it succeeds on a faulty verdict other than NOT_FALSIFIABLE, `note` says so and `attributable` stays false (does not occur).
13. **pb_detected** follows the task wording literally: faulty verdict is NOT_FALSIFIABLE and at least one faulty flag (any flag, not only rate flags) is in the expected list. So `K2_NO_SEPARATION` alone could give pb_detected true and attributable false. A faulty load error gives pb_detected false because the verdict is not NOT_FALSIFIABLE (P01).
14. **Condition (a), "the fixed study of the same arm carries no rate flag on s".** I take every rate flag (all those in item 5, expected or not) in the fixed twin's `components[0].flags`, map it to streams with the fixed bounds (item 9), and exclude stream s if it is in that set, whatever the flag type. So a fixed `K2_HIGH_SIZE` blocks `world:minus`, a fixed `K5_HOLDS_ON_NULL` blocks a faulty `HIGH_RATE:world:null` (P11), and a fixed `K4_CONTROL_ALSO_HOLDS` blocks the controls it maps to. Alternative (only expected flags in the fixed twin) is not used.
15. **Condition (b).** "exceeds" is strict (`holds_faulty > holds_fixed`) and "p < 0.05" is strict, tested exactly (`Fraction`), no multiplicity correction (the rule gives none). One-sided: H1 is that the faulty proportion is greater than the fixed one (upper tail of the hypergeometric, P(X ≥ faulty holds)), table `[[hF, nF-hF],[hX, nX-hX]]`. Rule: "the faulty count on s exceeds the fixed count, with a one-sided Fisher exact p < 0.05". The faulty and fixed `n` may differ; the general hypergeometric is used (they are always 200 in the data). The opposite direction is never tested.
16. **Stream missing from the fixed twin's counts.** The rule does not say. I treat the stream as not qualifying (reason "stream missing from fixed twin counts"), since (b) needs a fixed count and I do not impute 0. Does not occur in the data (the fixed twin lacks counts only when it has a load error, item 17). Stream missing from the faulty counts is likewise non-qualifying. Does not occur.
17. **Fixed load error.** Rule: "A stream does not qualify if the fixed study has a load error". All candidate streams of that pair are non-qualifying (reason "fixed study has a load error") and the pair gets an exclusion entry `fixed_load_error` (P09). The fixed twin then has no components, so there are no counts to compare either.
18. **Fixed hard UNDEFINED.** Rule: "or a hard UNDEFINED on s (`hard_undefined > 0`)". Checked per stream on the fixed twin's `counts[s].hard_undefined > 0`; the stream is non-qualifying and an exclusion entry `fixed_hard_undefined` with the stream is listed (P04, `world:minus`, 50). Other streams of the same pair are still evaluated independently. A hard UNDEFINED on the faulty side is not an exclusion in the text, so it is not applied (does not occur).
19. **Faulty load error.** Rule: "A faulty load error is not a detection." Listed as exclusion `faulty_load_error` (P01); no flags to evaluate.
20. **Each such case is listed.** Interpreted as: the exclusion list in `RESULTS.json` (`exclusions`) and the "exclusions" column in `RESULTS.md`. I list only the three listed kinds (faulty load error, fixed load error, fixed hard UNDEFINED); streams that fail for other reasons appear in `non_qualifying` with reasons, not in `exclusions`.
21. **Multi-stream flags and repeated streams.** `K4_CONTROL_ALSO_HOLDS` and `K5_HOLDS_ON_SHUFFLE` can map to several streams; the result has one qualifying entry per (flag, stream) pair. The same stream can appear under several flags (e.g. `world:minus` under both `K2_HIGH_SIZE` and `K2_FAILS_UNREACHABLE`). `qualifying_streams` is the deduplicated stream set, and generic/declared read this set. A stream can fail for several reasons; all are listed.
22. **Attributable** = faulty verdict NOT_FALSIFIABLE and at least one qualifying (flag, stream) entry (any one is enough, not all).
23. **The paired-test remark** ("a paired test is not available. Fisher's test treats the counts as independent") needs no choice: I use the independent-counts Fisher test and nothing else.

## D. Generic and declared

24. **Generic** = attributable and `probe:noise` is in the qualifying stream set. **Declared** = attributable and some qualifying stream is not `probe:noise`. Rule: "An attributable detection is **generic** if `probe:noise` is among its qualifying streams, and **declared** if a qualifying stream other than `probe:noise` exists. A detection can be both." Both are false when not attributable. No other stream is treated specially (e.g. `world:minus` counts as declared).
25. The B3-04 remark in the rule ("attributable under the rule, generic only") is not used by the code; it is only a check. The result here agrees: B3-04 is attributable, generic, not declared.

## E. Output conventions

26. `RESULTS.json` keeps all inputs I used (flags, expected list, counts used) so each decision can be audited. `qualifying[].fisher_p_one_sided` is the float of the exact fraction.
27. Rows are ordered acceptance P01..P13, then the PC cases in folder-name order.
